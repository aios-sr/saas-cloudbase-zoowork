# SaaS 项目开发

## 入口与边界

按用户的业务目标和目标仓库有效约定执行；已有选择或授权优先于本 Skill 默认项。仅在用户点名 $saas-cloudbase-zoowork 时执行本 Skill 并采用默认技术方案；不要把现有其他架构自动迁移为 CloudBase。

用简体中文沟通，保留技术专有名词。不要让产品人员决定 SDK 方法、变量拼写、版本锁定或租约算法。先读取已授权工具与项目记录；仅集中询问无法查明的业务信息、资源归属与必要授权。对缺失能力继续完成不依赖它的工作。

不从其他客户项目复制资料、资源标识或凭据。将 Key 保存在后端受控秘密配置；不要求聊天粘贴，不写入仓库、前端、日志、Agent 指令或任务序列化输出。将所有 Agent 调用固定到具体员工身份；不要用服务商 Key 或全局 ZooWork Key 执行 Agent。为公共定时 Agent 指定具体企业管理员成员。

## 1. 确定核心流程

读取目标仓库的 AGENTS、README、产品、架构及交接文档；新项目从用户描述中提取使用者、管理者、输入、处理流程、交付物和人工确认点。只在缺失时一次询问这些内容、品牌与终端、现有账号和仓库授权。

按 [产品模板](assets/templates/PRODUCT.md) 建立或精准补充目标项目的 PRODUCT.md，记录“已确认／假设／待确认”及至少一条可实际操作的验收路径；业务决策缺失时不伪造确认。给出分阶段计划及每阶段的验证目标，不预建未提出的支付、复杂审批或微服务。

## 2. 固定项目技术决策

初始化或修改基础设施时读取 [架构与配置](references/architecture.md)；查询接口、工具和依赖时从 [官方入口](references/links.md) 打开当前官方文档，并核对所装包类型。优先使用可用的 CloudBase 插件、技能或官方 CLI；工具不足时报告具体缺口。

在目标项目 docs/PROJECT_BASELINE.md 记录本 Skill 的名称、metadata.version、来源与可得的提交号、采用的默认项、例外及原因；同时记录已验证的非秘密环境信息。将依赖锁文件提交项目，不把版本候选当作兼容保证。

新仓库采用 [AGENTS 模板](assets/templates/AGENTS.md)，并将参考规则中实际采用的关键约束落实到项目内的架构、部署和交接文档；已有 AGENTS 只增补必要内容，不覆盖原规则。按 [环境变量模板](assets/templates/env.example) 生成 .env.example，并让实际读取、条件必填校验与文档一致。不要只复制变量而不实现后端配置读取。

先在安全界面完成必要登录；核对站点、账号、完整 EnvId、服务、认证和私有存储，再在授权范围内准备资源。保留测试与正式隔离，不因机器已登录而继承其他项目环境。

## 3. 完成可预览的业务闭环

按已确认产品流程实现登录、一个业务对象、任务提交、结果查看与保存；按 [数据与 UI 规则](references/delivery.md) 复用 ZooWork 完整组件骨架，连接真实业务回调。官方私有包不可取得时报告授权缺口，完成可独立验证的部分；需要替代组件库时先取得用户决定，不暗中更换。

实现后端租户与对象鉴权、增量迁移和私有文件访问。将预览明确标记为“受控演示”或“真实接通”；缺上游权限时不以假成功冒充业务完成。

## 4. 接入员工 Agent 与业务 Skill

在企业与成员开通、换钥或用量接入前读取 [ZooWork 合同](references/zoowork.md)；在任何 Agent、业务 Skill 或后台任务实现前读取 [Agent 与任务规则](references/agents-and-skills.md)。按目标服务的当前合同调用，不从示例推断实际权限或幂等能力。

先将成员映射和加密凭据准备为可验证状态，再按角色按需创建 Agent。按“应用、企业、成员、业务对象、角色”记录实例归属；每个任务固定原成员、凭据版本、Agent、Session 及规格快照。

有多个角色时，先从产品流程生成角色与依赖表，再按参考规则实现串行、并行和汇总；只有业务需要动态路由时才引入主 Agent。让后端控制权限、资料范围、状态、并发与重试；不要让模型扩大权限或替换执行身份。

将本应用业务 Skill 打包并记录不可变版本；在下一任务开始前安装及固定绑定。验证注册、绑定、挂载、实际读取与业务结果，分别报告证据。对仍在运行的任务保留原快照；遇到未知受理结果先核对远端，不重复创建或扣费。

## 5. 验证、PR 与交付

按 [验收与发布规则](references/delivery.md) 实现项目所需检查入口，运行有意义的身份隔离、版本、并发恢复与取消回归；核查桌面、窄屏、键盘和真实流程。按 [交接模板](assets/templates/HANDOFF.md) 记录“通过／失败／未执行”及证据，不用构建成功替代业务验收。

仅在已授权时执行会消耗 credits 的最小真实调用；保留执行身份与实际费用的可核验证据，不把无法归属的用量推算成精确成员账单。

从功能分支提交 PR；取得必要的合并与上线授权后，从已合并且干净的 main 发布，迁移、秘密绑定及业务 Skill 资源同样遵守门禁。新本地仓库还没有远程时记录该状态，不虚构 PR 或 CI，不擅自创建远程仓库。

向产品人员交付可打开的入口、可操作的流程、已知限制及必要决定；在项目内保存配置状态、检查、PR、发布版本和恢复办法。结束时说明实际完成范围，不把本 Skill 包的检查结果当作生成应用的云端验收。
