# 数据、UI、验证与发布

## 12. 数据、文件与交互

### 12.1 数据与文件

- 先设计企业、成员、业务对象、任务、资产和审计的稳定 ID／关系，再生成页面。私有记录都能追溯到租户和访问规则；新增结构使用新迁移，不能改已部署迁移。
- 数据访问使用参数化查询或官方受支持接口。事务、唯一约束和版本条件更新承担一致性；不接受浏览器传来的 SQL、对象存储路径或未校验归属 ID。
- 私有桶通过所属对象授权。应用下载端点检查归属；短期签名按最小范围与时效签发，需考虑撤销与缓存，不在日志或聊天中回显。
- 区分 PG 桶和其他存储接口，按已安装 SDK 类型检查返回值；上传失败不能继续声称资料已保存。生成文件按原任务和产物标识接收，核验来源、大小、类型和哈希后归档。
- 品牌公开资源、演示数据与客户附件分开。演示内容明确为虚构；不通过把整只私有桶改成公开来修复图片显示。
- 草稿恢复和缓存按企业、用户、业务对象及版本命名；退出或切换身份时清理相关状态，不让旧标签、附件和本地草稿混入另一客户。

### 12.2 UI 完整接入

Codex 先读已安装 UI 包的导出、类型和官方示例，再设计路由对应的页面骨架。

- 一级工作台优先使用完整 `PrimaryNavigation`、Logo、Item、Footer 组合；项目／业务对象页使用对应的 Workspace／二级导航，设置使用 `SecondaryNavigationLayout` 等适用组合。一级与二级导航按场景替换，不堆叠重复侧栏和页签。
- 表单、弹窗、菜单、提示、空状态、选择控件和账户内容优先复用现成组件。仅使用 tokens 不等于组件复用；保留主题祖先结构，不伪造标记或覆盖组件的选中、悬停、焦点和禁用样式。
- Chat 接通发送、停止、附件选择／上传／重试／移除、消息附件和引用等实际业务能力；没有能力的入口不放空操作。
- 仅在确认库内无匹配能力后自定义，在 `DESIGN.md` 记录边界。专业编辑器、图表或复杂画布按业务选用适配库，不从旧应用全量搬入。
- 核查桌面、窄屏、键盘、导航展开收起、移动抽屉、进入返回、对象切换和草稿保留。组件已渲染或导入数量增加不能作为验收结论。

UI 包需要 React／React DOM，获取和版本适配由 Codex 处理。依赖不可公开取得时，先检查已授权包或官方发布渠道并给出获取缺口；不得修改 `node_modules`、复制组件源码或悄悄换库后声称仍完整复用 ZooWork UI。

## 13. 用量、费用和异常披露

真实模型调用会消耗 credits，测试账号不代表免费。未明确授权真实调用时，先用受控传输完成回归；授权后的最小真实验收记录实际费用、执行身份、结果与限制。

- 余额与用量以 Partner 账务回执为准。区分企业总量、精确成员归属、共享与未知归属；后两者不推算成某员工的精确用量。
- Agent 用员工身份执行，与上游账务是否能精确归属是两件事。缺成员／Key／Session 关联时如实显示待核实，不以任务发起人补造关联。
- 默认只记录真实用量，不自行发明积分兑换、人民币价格或重复扣分；收费规则需明确后，按新任务的规则快照执行，历史不追扣。
- 金额／credits 使用十进制或适当定点数，遵守上游精度；不要把报表显示的舍入值当作余额或兑换校验原值。
- 积分不足、权限不足、限频、未就绪、超时、内容拒绝和产物接收失败分别提供可理解的状态；保留已保存资料，不泄露上游原始日志。

## 14. 统一脚本、诊断和验收

下列命令是新项目应提供的统一入口，须由 Codex 实现后才能使用，并在 README 记录；不是此文件自带的可执行脚手架。

| 入口 | 行为 |
| --- | --- |
| `npm ci` | 按锁文件安装已授权的依赖 |
| `npm run dev` | 启动前端，通过同源代理访问本地 API |
| `npm run dev:api` | 启动本地 Hono 后端，显式加载本地后端配置 |
| `npm run doctor -- --stage local` | 按 [前置合同](prerequisites.md) 检查 local／cloudbase／provision／agent／deploy；默认 local，只读且无开通、安装、发码或模型副作用 |
| `npm run methods:build` | 有自有 Skill 时生成确定的包与文件清单 |
| `npm run check` | 方法构建一致性、类型、有意义的回归及生产构建 |
| `npm run build:cloudbase` | 构建 CloudRun 前后端产物，验证目标 Node 运行方式 |

需要迁移、部署和维护脚本时，必须显式指定目标环境、检查当前提交与发布状态。应用启动不隐式运行破坏性迁移，不在每次启动时重复开通企业、成员或发布 Skill。

至少覆盖以下验收，并列出真实证据：

| 场景 | 必须验证 |
| --- | --- |
| 首次登录与刷新 | 原生身份与业务会话对应，退出与过期有效 |
| 两企业／同企业两员工 | 业务对象、正文、文件、Agent 和任务不越权 |
| 企业与成员开通 | 草稿／邀请不提前开通，重试不重复，前端无 Key |
| 无有效员工凭据 | 明确拒绝 Agent 执行，无全局回退 |
| 首个业务任务 | 创建／复用归属正确的 Agent，方法就绪，结果能保存和重载 |
| 方法或角色更新 | 版本、生效时机、旧实例和在途任务行为符合合同 |
| 并发与断线恢复 | 同一请求不重复创建／扣费，租约与游标可恢复 |
| 停用、换钥与取消 | 老客户端不能绕过复核，远端未知不标成已停止 |
| 文件原生显示与下载 | 登录与归属检查有效，授权例外不扩大到其他接口 |
| 定时服务（如启用） | 指定管理员、时区、日期去重、交接和缩容后触发有效 |
| 账务 | 上游量与披露一致，未知归属不伪造，历史不重复扣费 |
| 浏览器 | 桌面、窄屏、键盘和实际业务流程验证，不只看截图 |
| 秘密与隔离扫描 | 前端包、日志、响应、镜像及仓库中无真实秘密和客户资料 |
| 发布后 | 健康检查、原生登录、关键路径、资源访问与权限回归通过 |

配置、构建、受控测试、浏览器验收、线上接口和真实 AI 业务验收分开报告。某项未执行就列明未执行原因与影响，不用 CI 绿色或容器启动成功替代。

## 15. PR、上线和交接

1. 从最新 main 建功能分支；完成实现、检查和必要的预览后推送并创建 PR，写清行为、验证、迁移与回滚。
2. 工程变更先合并 PR，再从已合并提交与干净工作目录发布。不得直接向 main 推送，不从未合并分支或含未提交改动的目录部署，不先上线后补 PR。
3. 迁移、秘密绑定、服务设置、固定 Skill 资源与正式流量同属发布范围。准备好可审查变更清单，核对已有授权，不能绕过门禁先写生产。
4. 发布前确认账号、完整环境、服务、镜像／提交、资源和当前流量版本匹配。测试默认域名先验证原生登录、图片下载和沙箱回传；不能把平台提示页当成业务接口。
5. 完成线上验收，在 HANDOFF 或 PR 记录链接、提交、服务版本、迁移及实际结果；失败保留数据，优先关闭受影响能力或回滚兼容版本。
6. 删除共享执行路径后不回滚成“恢复全局钥”。旧账户迁移必须有明确映射，保留原用户与业务对象 ID；没有映射的历史数据不塞进默认企业。
7. 纯文档变更走 PR，无需部署。云资源、凭据和客户数据不因复制本文件而获得迁移或复用授权。

GitHub Actions 尚不可用时，完成本地检查并明确记录 CI 配置缺口，不把本地通过说成 CI 已通过。

交付给产品人员时优先提供：能打开的预览／正式入口、可以使用的业务流程、已知限制、需要其决定的事项。另附本地启动、环境配置状态、测试、PR、版本和恢复说明，让下一位开发者无需重新询问全部技术背景。
