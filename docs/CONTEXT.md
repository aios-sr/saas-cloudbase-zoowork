# 项目上下文与规范版本

## 开工、阶段回写与中断交接

每轮开工先读取目标项目 AGENTS、PRODUCT、PROJECT_BASELINE、架构、PRECHECK 与 HANDOFF，再核对当前分支、git status、未提交差异和最近提交；已有项目缺文件时先从可验证事实补最小记录。保留未提交改动，不通过 reset、清理或覆盖制造干净状态；来源不明时先梳理归属。以代码、迁移和实际验收核对记录，不将旧的“通过”当作当前配置仍有效。遇到影响业务或权限的冲突，标明已确认事实与待决定项，不从聊天残片猜测。

将新确认需求写回 PRODUCT，将技术决定及例外写回 PROJECT_BASELINE／架构，将前置状态写回 PRECHECK，避免多处维护同一事实。每完成一个可验证阶段，立即更新 HANDOFF 的已完成、正在做、验证、阻塞与下一步；较长任务在开始前先写当前目标和恢复点，不能只在整个任务结束时记录。意外中断后依据检查点和代码核实恢复，不直接重放可能有副作用的命令。

任务结束、切换或主动交接前保存可核对状态：分支与提交、尚未提交的文件、已执行／未执行检查、剩余步骤及必要入口。只摘要业务决定与证据，不复制内部对话、客户原文或秘密。把实际采用的关键规则保留在项目内，使新会话即使无法访问线上仓库也能按 AGENTS 继续；规范升级先审查差异并验证，不自动改写已有项目。

## 固定读取版本与权限

README 的分支链接用于发现入口。Codex 应通过可用的已授权 GitHub 工具或 Git 解析出完整提交，然后从该提交读取 VERSION、采用的章节和模板。在目标项目 docs/PROJECT_BASELINE.md 记录来源仓库、完整提交、文档版本、采用范围、关键规则摘要及例外；可按 [基线模板](../templates/PROJECT_BASELINE.md) 建立。

私有仓库通过已有安全登录读取；账号无访问权时报告缺口，继续不依赖缺失内容的工作，不能假称读完。离线副本必须包含同一提交的入口、引用文档与所用模板，并标明来源提交；没有提交号时记录未核验，不将其当成已验证的线上版本。

## 项目内持续开发

在项目 AGENTS 中规定每轮读取的项目文件与恢复步骤，并保留实际采用的架构、隔离、凭据、Agent 版本和发布约束。不要只写“参考线上规范”或绑定某台电脑的本地目录。PRECHECK 记录当前阶段的证据和时间，HANDOFF 只引用它并记录进度，避免维护两套配置状态。

线上仓库临时不可访问时，已有项目可以基于自己的已确认记录继续不依赖新资料的工作；不能猜测更新内容或丢弃已有改动。新增能力确实需要缺失规则时，明确受阻部分并集中补齐资料。

## 升级规范

已有项目不会自动跟随 main。先将当前基线提交与拟采用的新提交作差异审查，再记录对依赖、权限、数据、任务、测试和发布的影响；仅将所需变化经项目 PR、验证和授权引入。保留旧基线和迁移记录，历史任务仍按原身份与快照恢复。

本规范文档不是应用运行时配置；应用不能在每次用户任务中下载 main 并执行其中的新规则。
