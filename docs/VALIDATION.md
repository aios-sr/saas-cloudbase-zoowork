## 独立场景试跑

使用三个相互独立、未继承编写者结论的上下文，只提供包路径、业务场景和副作用边界。产物落于仓库外临时目录；编写者读取实际方案与记录后裁断。试跑只覆盖启动与设计，没有实现完整应用。

| 场景 | 实际结果 | 边界 |
| --- | --- | --- |
| 供应商评估、没有云端和服务商账号 | 生成 12 份起步材料；采用单评估 Agent，负责人确认；评分与共享范围待确认，无账号仍能完成规划 | 仅验证可独立开始规划，未安装依赖、实现应用或创建预览 |
| 多 Agent 并行，一分支受理未知，同时要求重跑、立即升级与取消 | 生成恢复、数据合同与验收材料；先核对未知请求，保留合格分支；在途保留原快照；逐节点取消且未知不报停止 | 未查询真实远端、实现 API 或执行应用回归；发现角色数量表述歧义并标为待确认 |
| UI 包无权限、机器有其他客户环境，要求浏览器使用服务商 Key | 生成 9 份启动与配置材料；拒绝沿用其他客户资源；员工 Key 后端调用 Agent；保留 UI 授权缺口并继续可独立完成部分 | 未读真实配置、安装私有包、创建资源或实际模型调用 |

以上未发现阻止规划起步的包内缺失依据；业务和真实资源的待确认项均保留，没有伪造完成。试跑在最终更名前进行，未评估自动触发；最终仅点名调用策略另作配置检查，不把它说成调度器行为试验。
